- Gate reframing (B5): B5 = dynamic coverage selection (run every test covering the changed line). On mutants it has recall 1.0 by construction, so recall@k alone is the wrong test. The M6 gate must report, against B5: (a) tests needed for 95% recall (`n95`) and the ratio to B5's covering-set size (`n95_vs_B5`; <1 means fewer tests than B5), (b) suite-time fraction at 95% recall, and (c) whether a model can match B5 *without* per-test coverage maps (cost of keeping maps fresh is B5's weakness; B5 here uses coverage computed at exactly P, i.e. the best case for B5). Evaluator now emits n95 / n95_vs_B5. Current result (h3, 12 parents): no non-coverage ranker beats B5 on test count; B4 (no coverage maps) is the closest and only approaches B5 in the >10-covering-tests stratum.
- Shortcut caveats recorded: (1) fails⊆covers is an artefact of the labelling shortcut; a non-covering test that really fails (shared state, fixtures, config, mocks, subprocesses) would be mislabelled as passing, which can only flatter structure-based rankers and hurt B2/B3, so any leakage is biased toward our hypothesis. (2) The first validation (24 mutants, 3 commits) is narrow and the 0/24 result is weak evidence; violations would cluster in hub files and module-level code. A second, risk-targeted validation (5 highest-risk mutants per parent over all 12 parents, ranked by transitive importer count and module top-level location, plus 1 random each) is running: data/shortcut_check_risky.json. (3) Not applicable to real-commit labels: real commits were labelled with full-suite runs (no shortcut), but commits touching config/fixtures/non-src files have no line coverage, so `covers` is undefined for them; do not use covers-based labels or B5 on such commits.
- M4 reframing (after B5 review): M1 should be "B5 plus learning": coverage as a filter, structure (call distance from mutated function to test, reverse-dep depth, test targetedness) and history as ranking features inside the covering set. Report `n95` relative to the BEST of B5a/B5b/B5c. B5b (most targeted first) and B5c (historical failure order) added; on h3 neither beats B5a (random order within the covering set) by a meaningful margin, and B5b is clearly worse in the >10 stratum (recall@5 0.105 vs 0.377 on test split), so naive "targeted" orderings do not help; ranking inside the covering set has real room (B5a still needs ~80-84% of the covering tests for 95% recall in the >10 stratum).
- Decision-gate addition: coverage-free is only worth building if it wins somewhere B5 cannot operate (config/fixtures/new or renamed files/stale maps). If M1 only ties B5b, the honest conclusion is "use coverage", which is a clean finding.
